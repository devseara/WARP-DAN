# HD job previews — 2025-07-16 x86

`HDJobSpritePreviews` redirects four Equipment (Alt+Q) and five Skill Tree (Alt+S) resource calls to generated native-size UI SPR/ACT pairs. World rendering and world resource paths remain unchanged. Resource coverage is generated from the supplied archive chain; there is no fixed job-ID list in the native bridge and no runtime sprite resizer. New or replaced HD artwork requires regenerating the assets and repatching the client.

Generated SPR/ACT files and their manifest are excluded from Git. Supply or generate the `Assets/HDJobUI` pack separately before applying this patch. Existing local/client assets are retained when the pack is untracked. WARP checks every required file before allocating or changing the executable and reports the generation command if a file is missing.

## Resource coverage

The installed archive audit resolved 2,206 complete body pairs: 61 have non-unit ACT scales and 2,145 have native scales. All 61 scaled paths are in the locally generated manifest, including male/female costume, Madogear and Doram variants. They share 18 unique preview/fallback sets where all generated bytes match. Ten ACT-only paths have no SPR anywhere in the supplied chain and are reported as unpaired; they are not assigned substitute artwork. See [coverage inventory](evidence/hd-job-ui/coverage.json).

Discovery resolves SPR and ACT independently in file-priority order. An ACT override in one GRF can correctly pair with a SPR from a lower-priority archive. Native overrides shadow lower-priority scaled assets. Archive tables stay open during a build and close afterward. Loose roots, when explicitly supplied, precede source GRFs; for an archive-first client, pass its archives in priority order without a loose root.

The original supplied HD assets are 4× male/female clan Swordman (ACT 0.25) and 2× male Monk high (ACT 0.5). The test world archive explicitly assigns the same Monk HD artwork to normal male Monk because live resource tracing identified `몽크_남`, while the supplied file was named `몽크_h_남`. These are asset-map entries, not class-specific scaling code. Other discovered non-unit scales include stock animation scaling and should not be described as additional HD artwork.

## Size and alignment contract

For each visible ACT layer, generate `round_half_up(SPR.width * scaleX)` by `round_half_up(SPR.height * scaleY)` pixels and set the UI ACT scales to `(1, 1)`. Fractional factors, nonuniform axes and per-frame scale changes are supported. Reused images with different resulting dimensions receive additional image variants, and only the referring ACT indices change. Frame/action order is preserved. Raster rounding can differ by half a pixel per axis; positive subpixel dimensions become one pixel.

This matches logical world dimensions. Camera zoom and runtime transformations are outside the ACT scale and are not copied into UI windows. The profiled loader computes `trunc(file_offset / layer_scale) - floor(source_dimension / 2)` before world geometry applies layer scale. UI ACT X/Y offsets therefore remain the original logical coordinates. Multiplying them by the HD factor again breaks alignment. Anchors, mirror, color, rotation, frame headers, sounds, timing and unrelated bytes stay unchanged; ACT 2.5 dimension fields follow the generated images.

Resampling uses premultiplied-alpha Lanczos. Truecolor SPR is bottom-up ABGR. Indexed sprites retain their palettes and dye mechanism; quantization excludes transparent index zero and uses binary transparency because indexed SPR cannot store partial alpha. Stock fallback pairs are validated; any original stock ACT scaling is baked into their native-size copies with the same rules. Their original world resources remain untouched.

Supported formats: SPR 2.0/2.1/2.2 and ACT 2.4/2.5. Invalid references, unsupported complete pairs, nonpositive/nonfinite scales and excessive dimensions fail the build. Limits: 2,048 resource paths, 65,535 variants per image type, 4,096 pixels per output axis and 64 million output pixels per pair. The untracked `Assets/HDJobUI/manifest.json` records source/output hashes, scales and resource mappings.

## Regenerate coverage

Dependencies: Python with Pillow, pefile and Unicorn; MSVC x86 compiler/linker; WARP console and the profiled reference EXEs for integration checks. The compiler and baseline location can be overridden with `--compiler` and `--profile-client`.

```powershell
python tools/hd_job_ui_assets.py `
  --source-grf 'C:\client\hd_world.grf' `
  --source-grf 'C:\client\update.grf' `
  --source-grf 'C:\client\spritedata.grf' `
  --stock-grf 'C:\stock\spritedata.grf' `
  --write-config Outputs/hd-job-ui/coverage-config.json `
  --output Assets/HDJobUI
python tools/build_hd_job_ui.py
```

Repeat `--source-grf` and `--stock-grf` in their respective priority orders. Stock archives must provide the intended stock artwork. `--sprite-root` accepts a folder below `sprite/`, with either decoded Korean or legacy Latin-1 mojibake Windows names. Discovery covers all species `*/몸통/` paths, including clan prefixes, and skips preview namespaces. It requires a complete stock fallback for every scaled body.

For custom names or explicit artwork assignments, use `--config` instead of discovery inputs:

```json
{
  "pairs": [{
    "id": "custom_job_m",
    "resource_stem": "custom_jobs/body_m",
    "source": {"path": "C:/assets/body_m"},
    "fallback": {"grf": "C:/stock/sprites.grf", "stem": "data/sprite/인간족/몸통/남/검사_남"}
  }]
}
```

Paths omit extensions. A specification can use `path`, `grf` plus `stem`, or separate `spr` and `act` specifications when files resolve from different archives. `--write-config` saves the exact resolved map and reports unpaired ACT paths. Generate all desired jobs together; the manifest is replaced and only its files deploy.

After generating the separate asset pack, select **Native-size HD Job Previews (Alt+Q / Alt+S)** in WARP. It copies the required files beside the output EXE under `data/sprite/hd_job_ui/`. Copy that directory with the EXE. The profiled loader tries loose files after an archive miss even with folder-first disabled. Keep the namespace unique: an old copy in a higher-priority GRF would win. An optional UI archive can be built with:

```powershell
python tools/package_hd_job_ui_grf.py --assets Assets/HDJobUI --output Outputs/hd-job-ui/hd_job_ui.grf
```

Register that archive in the client's active GRF list. `--world-config` instead packages unchanged original world pairs from an explicit map; it is independent of UI conversion.

## Native contract

Only 2025-07-16 is accepted. Before allocation or mutation, the patch verifies all nine original call bytes and six profiled native prologues. Accepted starting layouts are stock and the verified ClanBodySkins v11 bridges; mixed/unknown layouts are rejected. WARP can retain already-applied metadata, so rebuild from the previous input EXE after changing assets.

| UI | Call VAs | Native ABI |
|---|---|---|
| Equipment | `7ACD71`, `7ACDB1`, `7AEC6B`, `7AED3F` | `A8D9F0`, thiscall, owned 24-byte MSVC string by value, callee pops 24 |
| Skill Tree | `974B20`, `974B56`, `974B76`, `974D35`, `974E04` | `A8D4A0`, thiscall, const char pointer, callee pops 4 |

Both bridges preserve the resource manager in ECX. Equipment reassigns its owned string and transfers it once to the native loader, which destroys its storage. Unlisted resources delegate to the original loader or v11 bridge (`01967BF0` / `01967C30`). Listed resources use distinct preview/stock names and resolve directly through the native loader. CP949 lead/trail bytes survive ASCII normalization. No world hook, DLL, packet hook or text renderer is changed.

Both preview members are checked before either is loaded. Missing SPR or ACT selects the packaged stock pair for both extensions. The choice is cached for the process lifetime; restart after modifying resource files. Resource object pointers are never cached. Stock fallback files are deployment requirements.

CFile: 44-byte object, vtable `FD3074`, handle -1, embedded 24-byte string at +20, Open `573750` with `(path,0,1,0)`, Close `573060`, string destructor `4F08F0`, string assign `4F1940`.

Baseline SHA-256: `73349f3606de8e9535d91b73e0177813c38369f06795f5a91200715a177f1a9f`.
ClanBodySkins v11 SHA-256: `f0d962c64c0449eaec24010c75a331ee087a4807fb8bdd42e3d097680e99709c`.

## Embedded GRF list and test client

The supplied v11 client embeds its archive list; editing external DATA.INI alone does not update it. `tools/rebuild_hd_job_ui_test.py` verifies the v11 hash, complete embedded-loader structure and unique startup call before rebuilding that list. Profile: stub `0181F2F0`, call `00DB98B6`, AddPak `00A88890`, manager `0159D410`. Original archive names/order are retained, and all listed GRFs must exist. An explicit `--data-ini` permits an isolated test list. `--label` is required; existing outputs are never overwritten. The tool verifies emitted AddPak order/ECX/stack cleanup and restricts existing executable changes to that startup call and the nine UI calls.

```powershell
python tools/rebuild_hd_job_ui_test.py `
  --source 'C:\references\clan-skins-v11-check.exe' `
  --client-dir 'C:\client' --data-ini 'C:\client\DATA.INI' `
  --label v5 --only-check --deploy
```

The retained v4 client and `hd_job_ui_v4_world.grf` are the accepted Monk fixture. The expanded v5 client uses the same world archive and all 61 UI routes, with no diagnostic ring or process reader. The main client EXE is not replaced.
